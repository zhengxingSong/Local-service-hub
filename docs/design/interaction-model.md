# 服务中枢 — 交互模型与信息架构（讨论稿）

> 目的：先把「用户要完成的闭环」定下来，再由闭环反推页面、浮层与按钮布局。
> 视觉设计（配色/字体/材质）留到 IA 确认之后。本文件只回答：几个页面、每个页面放什么、什么该是浮层。

## 0. 约束

| 约束 | 值 | 影响 |
|---|---|---|
| 窗口尺寸 | 1120×780，最小 860×600 | 横向空间有限；左侧栏会明显压缩列表宽度 |
| 使用形态 | 托盘常驻，绝大多数时间是「唤起→看一眼→收起」 | 首屏必须直接回答「都活着吗」 |
| 用户 | 单机单用户，懂技术的本人 | 不需要权限、不需要引导 |
| 服务形态 | llama / 命令 / 容器 三类 | 列表要能混排；编辑表单按形态切换 |
| llama 能力 | 可选面板（未配置时不应出现） | 「模型」相关页面必须是条件出现的一级页 |

## 1. 使用情境（按频率分层）

**高频（每次打开都发生）**

- J1 巡检：现在什么在跑？谁挂了？挂了多久？为什么？
- J2 组切换：我要把 OpenViking 三件套换成 27B 聊天（显存互斥）
- J11 资源判断：显存快满了，停谁？

**中频（出问题时）**

- J6 排障：某服务起不来 / 反复重启 → 看错误 → 看日志 → 修正 → 重启
- J12 取日志：把日志复制出去或直接打开目录
- J9 外部改配置：手改了 services.json，要让应用接上

**低频（配置期，偶尔）**

- J3 新增服务：纳入一个新东西
- J4 试模型：发现一个 GGUF，先临时跑一下，满意再转正（llama 专属）
- J5 下载模型：本机没有，搜/直链拉下来（llama 专属）
- J7 组管理：定义常用组合、标记独占
- J8 全局设置：改 llama 路径、扫描根、重启上限、显存阈值、登录自启
- J10 退出：决定是否连服务一起停

## 2. 交互动作清单

### 全局

| 动作 | 触发点 | 反馈 |
|---|---|---|
| 唤出窗口 | 托盘单击/双击、二次启动 | 窗口前置 |
| 隐藏窗口 | 关窗按钮 | 收进托盘（服务继续跑） |
| 进入设置 | 顶栏 | 设置页 |
| 退出应用 | 顶栏 / 托盘菜单 | 有运行中服务时先确认 |
| 应用外部配置变更 | 内联提示条 | 只重启参数变化且运行中的服务 |

### 服务（对单个服务）

| 动作 | 前置条件 | 反馈 |
|---|---|---|
| 启动 | 已停止/失败 | 行状态：启动中 → 就绪中 → 运行中 |
| 停止 | 运行中/就绪中/启动中 | 行状态：已停止；等进程真正退出 |
| 重启 | 运行中/失败 | 行状态：重启中 → 就绪中 → 运行中 |
| 编辑 | 任意 | 二级编辑页 |
| 删除 | 任意（运行中先停） | 确认模态 → 行消失 |
| 切换自启 | 任意非体验服务 | 即时保存 |
| 查看详情+日志 | 任意 | 右侧抽屉（不离开列表） |
| 清空日志 | 抽屉内 | 日志区清空 |
| 打开日志目录 | 抽屉内 | 系统资源管理器 |
| 转正（体验服务） | 体验中 | 确认 → 变持久服务（沿用启动参数） |
| 放弃（体验服务） | 体验中 | 确认 → 停止并移除 |

### 预设组

| 动作 | 反馈 |
|---|---|
| 启动组 | 逐服务启动；独占组冲突时先确认 |
| 停止组 | 逐服务停止 |
| 新建/改名/加成员/标记独占/删除组 | 组管理模态 |

### 模型（llama 专属）

| 动作 | 反馈 |
|---|---|
| 扫描/刷新模型 | 列表更新（主进程 10 秒缓存） |
| 一键体验 | 临时服务行（体验标记、自动端口、不写配置） |
| 下载模型（按名称 / 直链 / 可选 SHA256） | 抽屉或模态内显示进度、可取消 |
| 模型 → 创建持久服务 | 进编辑页并预填 |

### 设置

| 动作 | 反馈 |
|---|---|
| 改 llama-server 路径 / 模型扫描根 / 模型目录 | 影响模型页是否出现与扫描结果 |
| 改崩溃重启上限 / 显存告警阈值 / 登录自启 | 即时生效 |
| 显示或隐藏 llama 面板 | 顶栏标签增减 |

## 3. 交互闭环（12 个）

每个闭环写清：触发 → 感知 → 决策 → 动作 → 反馈 → 闭环判据。

**L1 巡检闭环（最高频）**
触发：唤起窗口 → 感知：顶栏摘要「运行 5 · 就绪中 1 · 失败 0」+ 行状态色 → 决策：无需动作则收起；有失败则点该行 → 动作：抽屉看错误与日志 → 重启或编辑 → 反馈：行状态回到运行中 → **闭环判据：顶栏摘要失败数归零**。

**L2 组切换闭环（含独占）**
触发：点组「启动」→ 感知：提示将停止的其他组与预计释放显存 → 决策：确认或取消 → 动作：依次停止旧组（等端口释放）→ 启动新组 → 反馈：组状态变为「运行中 2/2 就绪」→ **闭环判据：新组全部服务达到就绪，旧组全部停止**。

**L3 新增服务闭环**
触发：新增 → 感知：三种形态选择 + 必填校验 + 端口占用预检 → 决策：填哪个形态 → 动作：填表 → 保存 → 列表出现（已停止）→ 启动 → 反馈：就绪 → 决策（可选）：设为自启 → **闭环判据：新服务在列表中稳定显示运行中**。

**L4 体验→转正闭环（llama）**
触发：模型页看到未纳管模型 → 动作：一键体验 → 感知：临时行（体验标记 + 自动端口）→ 试用 → 决策：转正或放弃 → 动作：转正（沿用参数写配置）或放弃（停止并移除）→ **闭环判据：临时行消失，或被一条持久服务替代**。

**L5 下载闭环（llama）**
触发：模型页下载入口 → 动作：按名称搜索选型，或填直链（可选 SHA256）→ 感知：进度 + 可取消 → 决策：等待或取消 → 动作：（成功后）选择创建服务或一键体验 → 反馈：进入 L3/L4 → **闭环判据：文件落入模型目录且出现在模型列表，或用户明确放弃**。失败分支：大小/哈希不符 → 报错（哈希不符删除分片；大小不符保留分片可续传）→ 可重试。

**L6 排障闭环**
触发：某服务显示失败 → 感知：行内错误摘要 → 动作：打开抽屉看完整错误与日志 → 决策：按错误类型判断（端口占用 / 模型缺失 / 命令不存在 / 显存不足 / 参数错误）→ 动作：编辑修正，或停止占用者，或降低 ctx/ngl → 重启 → 反馈：就绪 → **闭环判据：lastError 清空且状态为运行中**。

**L7 日志导出闭环**
触发：抽屉内 → 动作：复制片段 / 打开日志目录 / 清空 → 反馈：目录打开或内容清空 → **闭环判据：用户拿到日志**。

**L8 设置维护闭环**
触发：顶栏设置 → 动作：改项 → 保存 → 反馈：Toast「配置已保存」+ 即时生效（运行时参数、自启注册表）→ **闭环判据：设置项持久化且行为已变**。

**L9 外部配置变更闭环**
触发：外部修改 services.json → 感知：内联提示条「配置已变化」→ 决策：应用或忽略 → 动作：应用 → 反馈：「已重启 N 个服务」+ 列表刷新 → **闭环判据：提示条消失，运行中的服务与新配置一致**（点忽略则提示消失，下次变更再出现）。

**L10 退出闭环**
触发：退出按钮 → 感知（仅有运行中服务时）：列出服务 + 是否同时停止 → 决策 → 动作：停服务或保留 → 退出 → **闭环判据：应用退出；服务状态符合用户选择**。

**L11 资源告警闭环**
触发：显存超过阈值 → 感知：顶栏显存态变警示 + 摘要里出现告警项 → 动作：点开看出占用最大的服务 → 决策：停谁 → 动作：停止 → 反馈：显存回落 → **闭环判据：显存低于阈值，告警消失**。

**L12 组管理闭环**
触发：组管理入口 → 动作：新建/改名/增删成员/标记独占 → 保存 → 反馈：组条更新 → **闭环判据：组按新定义可一键启停**。

## 4. 闭环 → 界面承载（建议）

原则：**高频动作零层级，中频动作不丢上下文，低频动作不占首屏。**

| 承载 | 类型 | 承载的闭环 |
|---|---|---|
| P1 服务 | 一级页（默认） | L1, L2, L9, L11, L12(入口), L3(入口) |
| P2 模型 | 一级页（仅配置了 llama 能力时出现） | L4, L5 |
| P3 设置 | 一级页 | L8, J7 |
| P2.1 服务编辑 | 二级页（宽模态或整页） | L3(填写), L6(修正) |
| D1 服务抽屉 | 右侧抽屉 480px | L6, L7, L11(定位) |
| M1 确认模态 | 居中模态 | L2(独占切换), 删除, L10 |
| M2 组管理 | 居中模态 | L12 |
| M3 下载 | 居中模态 | L5 |
| T1 Toast | 右下，4 秒 | 所有动作结果（已启动/已停止/已保存/下载完成/失败原因） |
| B1 内联提示条 | 页面内顶部，非浮层 | L9, L11 |

不建议做成一级页的两项，及理由：

- **日志**：绝大多数日志访问源于「某个服务出问题」，从服务行进入抽屉最自然，且不丢列表上下文。跨服务时间线是增强项，将来可以整体搬到 P4「日志」而不改任何交互（抽屉内容原样复用）。
- **总览/仪表盘**：窗口只有 1120×780，独立仪表盘会把「启停」这个高频动作推到第二个页面。摘要信息（运行 N / 失败 M / 显存 X%）压缩进顶栏即可满足巡检。**这是本稿最需要你拍板的一处取舍**（见第 6 节）。

## 5. 各承载上的元素清单

### 顶栏（44–48px，唯一全局条）

- 左：产品名 + 全局状态摘要（运行 N · 就绪中 N · 失败 N）+ 显存 X%（超阈值转警示色）
- 中：一级页标签（服务 / 模型 / 设置）
- 右：搜索（按名称/端口过滤服务）、设置、退出

### P1 服务页

- **组条**：每个预设组一个胶囊（名称 + 成员就绪数 + 启停）；独占组带锁标记；末尾「管理组」
- **服务列表（行式，不是卡片）**，每行：
  - 左侧状态条（4px 竖条，色 = 状态）+ 状态文字
  - 名称 + 形态徽章（llama / 命令 / 容器）+ 角色
  - 关键指标一行：端口 · 就绪判定 · 显存 · 重启次数（次要信息收进抽屉）
  - 主操作：1 个按钮（按状态：启动 / 停止）
  - 溢出菜单：重启 / 编辑 / 日志 / 自启开关 / 删除
  - 整行可点 → 打开抽屉
- **底部固定区**：新增服务
- **失败行**：错误摘要直接显示在行内第二行（红色小字，单行省略），点击展开抽屉
- **工具栏**：过滤器（全部 / 仅运行 / 仅失败）+ 排序

### D1 服务抽屉（右侧 480px）

- 头部：名称 + 形态 + 状态 + 就绪判定结果 + 主操作（启动/停止/重启）
- 信息区：PID、端口、alias/命令、cwd、模型路径（可复制）、显存估算/实测、退出码、重启次数、最近启动/结束时间
- 日志区：尾部 16000 字符，2 秒自动刷新（仅可见时）、清空、打开目录
- 底部：编辑、删除、自启开关

### P2 模型页（llama 专属）

- 已纳管模型（已在服务中引用的模型）：与其服务行互链
- 未纳管模型库：卡片或行 + 「一键体验」
- 下载入口：按名称 / 直链 / SHA256
- 说明区：模型目录、扫描根（与设置页共享数据，此处只读展示 + 跳转）

### P3 设置页

- llama 能力：llama-server 路径、扫描根、模型目录、显示模型面板
- 运行：崩溃重启上限、显存告警阈值、登录自启
- 数据：配置文件路径、日志目录（打开）、服务端数据迁移说明（只读）

### 二级页 P2.1 服务编辑

- 形态选择（llama / 命令 / 容器）
- 按形态切换的字段区
- 就绪判定（4 选项 + 条件字段）
- 自启 / 启用
- 底部：取消 / 保存
