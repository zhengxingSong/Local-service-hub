## 1. 容器总清单

| 代号 | 容器 | 类型 | 职责 | 尺寸 |
|---|---|---|---|---|

| **B2** | 内联条（资源告警） | 页内 | 超阈提示 + 跳到占用者 | 资源面内 |
| **I1** | 就地展开（成员明细） | 卡内 | 该用途的成员逐行 | P1 卡内 |

## 4. 浮层清单与触发条件

| 浮层 | 触发条件 | 关键约束 |
|---|---|---|
| **M1 预检** | 任何启动/启用/切换，且四族**至少一族不通过** | 全过时**不出现**；只展开有问题的族，其余折成"✓ 无问题" |
| **M2 危险确认** | 删除服务 / 解散组 / 强制停止 / 快照回滚 / 退出 | 五种**各有专属文案**，不许共用"确定吗" |
| **M3 素材获取** | 素材未就位或损坏；或手动发起下载 | 进度可取消；哈希不符则删除损坏分片 |
| **M4 探测** | 新建服务第一步 | 给建议形态 + 已推断字段，用户可改 |
| **M5 组编辑** | 新建/编辑预设组 | 成员顺序即启停顺序，界面上必须写明 |
| **D1 服务运行时抽屉** | 运行态点成员行 / 卡内「处置」 / 清单行「运行记录」 | 打开不离开当前页；承载处置层全部内容 |
| **T1 Toast** | 所有动作结果 | 失败 Toast 常驻到手动关闭；成功 4 秒 |
| **B1 内联条** | 外部修改 services.json | 应用前先给**差异清单** |
| **B2 内联条** | 资源超阈值 | 只提示 + 跳占用者，不自动抢占 |
| **TR 托盘菜单** | 右键托盘 | 打开主界面 / 快速启用某用途 / 退出 |
| **NT 系统通知** | 服务崩溃、重启达上限 | 与卡上的异常态指向同一处（D1） |

### 5.3 覆盖结论

- **55 项行为全部有归属，无家可归 0 项。**
- **没有任何容器是空转的**：承载最少的 NT 系统通知也有 1 项职责（它是 54 的唯一出口，且与卡上异常态指向同一处 D1）。
- 有 5 项行为**合法地有两个入口**（不视为重复）：13 看定义（P2 行菜单进入 P2.1）· 24 准备（P2.1 与素材页签）· 35 打开目录（P3 与 D1）· 37 复制（D1 与 P2.1）· 45 释放（资源面与 M1）。判断标准是**入口不同、目的相同**——若目的不同则应拆成两项行为，而不是硬塞两个入口。

## 6. 与 surfaces.md 的两处差异（说明改了什么、为什么）

| 变更 | 原设计 | 现设计 | 原因 |
|---|---|---|---|
| **服务"定义"不再放抽屉** | 配置态与运行态的详情共用一个抽屉，两个页签 | 配置态 → P2.1 二级页；运行态 → D1 抽屉。D1 内提供「编辑定义 →」跳转 | 六段表单在 440px 抽屉里太挤；且**编辑是施工、观察是使用**，两种心态共用容器会互相牵制。分开口，靠跳转保证可达 |
| **处置层宿主改为抽屉** | 从异常卡**卡内**展开 | 卡内只到成员行 + 一行异常摘要 + 「处置」；点开后内容进 D1 | 处置内容很长（归因 + 日志 + 记录 + 修正），卡内展开会把用途列表挤走。抽屉不离开当前页，同样保住"其它用途还可用吗"这个上下文 |

## 7. 布局约束与自查

1. **主列只有一种对象**：P1 主列只有用途卡，P2 主列只有服务行。任何页面不许同时以两种对象为主体——这是"信息密度大而找不到重点"的结构性防线。
2. **窗口容量已核算**：1120×780 下 P1 一屏 5–6 张用途卡（当前 5 个用途刚好一屏）、P2 一屏 15 行以上、P2.1 左栏固定 200px 右栏自适应。
3. **最小尺寸 860×600 下的退化**：P1 资源面从 300px 收到 240px 并允许折叠；P2.1 左栏收成 48px 图标条；P2 表格隐藏"暴露"列（进详情看）。
4. **模态永远只有一个**：同屏不允许叠两个模态（M1 与 M2 若同时需要，先 M1 后 M2）。
5. **每个容器都有明确的进入与离开条件**：没有"顺手停留"的状态；P1 是默认，P2/P3 有返回，浮层有取消。
6. **仍未覆盖的设计项**（要在实现前补）：探测的具体交互（M4 内部）、可视化参数面板与原始参数的往返、Toast 的具体文案模板、键盘与无障碍（焦点顺序/快捷键/reduced-motion）、最小尺寸下 P1 资源面的折叠交互。
